# Mean Model with Docker Support

This example demonstrates a CHAP-compatible R model with full Docker and renv
environment support. Use this as a template for creating containerized R models.

## Directory Structure

```
mean_model_docker/
  model.R           # R model using create_chap_cli()
  main.py           # Chapkit service entry point
  renv.lock         # R dependencies (generated by renv::snapshot())
  chap.yml          # Environment configuration (optional)
  Dockerfile        # Generated by generate_dockerfile()
  .Rprofile         # renv activation (auto-generated)
  renv/
    activate.R      # renv bootstrap script
```

## Quick Start

### 1. Initialize the Environment

In R console, from this directory:

```r
library(chap.r.sdk)

# Initialize renv and create chap.yml
init_chap_env()
```

This will:
- Initialize renv for reproducible R dependencies
- Add chap.r.sdk to your dependencies
- Create `renv.lock` with exact package versions
- Create `chap.yml` for environment configuration

### 2. Add Additional Dependencies

Install any additional R packages your model needs:

```r
renv::install("dplyr")
renv::install("purrr")
renv::snapshot()  # Update renv.lock
```

### 3. Generate Dockerfile

```r
generate_dockerfile()
```

This will:
- Read R version from `renv.lock`
- Auto-detect system dependencies (apt packages)
- Generate a multi-stage Dockerfile

### 4. Build and Run

```bash
# Build the Docker image
docker build -t mean-model .

# Run the service
docker run -p 8000:8000 mean-model

# Access the API
curl http://localhost:8000/health
```

## Environment Configuration

The `chap.yml` file allows you to override default settings:

```yaml
environment:
  # Override base image (default: rocker/r-ver:{R_VERSION})
  base_image: null

  # Additional apt packages beyond auto-detected
  extra_system_deps:
    - libgdal-dev
    - libproj-dev

  # Chapkit version constraint
  chapkit_version: ">=0.1.0"
```

## Testing Locally

You can test the model locally before containerizing:

```bash
# Test the CLI
Rscript model.R info --format json
Rscript model.R train --data example_data.csv
Rscript model.R predict --historic example_data.csv --future future_data.csv --output predictions.csv

# Test the service
python main.py
```

## CI/CD Integration

Example GitHub Actions workflow for building and pushing the image:

```yaml
name: Build Model Image

on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build Docker image
        run: docker build -t ghcr.io/${{ github.repository }}:latest .

      - name: Push to registry
        run: |
          echo ${{ secrets.GITHUB_TOKEN }} | docker login ghcr.io -u ${{ github.actor }} --password-stdin
          docker push ghcr.io/${{ github.repository }}:latest
```

## Generated Dockerfile Structure

The generated Dockerfile uses a multi-stage build:

1. **Stage 1 (r-env)**: Base R image with renv packages
   - Installs system dependencies
   - Copies renv files for layer caching
   - Runs `renv::restore()` to install R packages

2. **Stage 2 (runtime)**: Adds Python and chapkit
   - Installs Python and pip
   - Installs chapkit
   - Copies model code

This structure ensures:
- Efficient layer caching (R packages only rebuild when renv.lock changes)
- Clean separation of concerns
- Minimal final image size

## Troubleshooting

### System Dependencies Not Detected

If a required system library is missing, add it to `chap.yml`:

```yaml
environment:
  extra_system_deps:
    - libcurl4-openssl-dev
```

### R Package Installation Fails

Check if the package requires system libraries. Common mappings:
- `curl` -> `libcurl4-openssl-dev`
- `xml2` -> `libxml2-dev`
- `sf` -> `libgdal-dev libgeos-dev libproj-dev`

### Image Build Is Slow

- Use Docker BuildKit: `DOCKER_BUILDKIT=1 docker build ...`
- Ensure layer caching by not modifying renv files unnecessarily
- Consider using a base image with common packages pre-installed
